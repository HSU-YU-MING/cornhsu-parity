# 開發者使用者視角實查(DX):0.12.0(已發佈)vs 準 0.13.0(PR #26 分支)

**日期**:2026-08-11。**方法**:從 NuGet 安裝真實發佈的 0.12.0,以「第一次接觸的開發者」
身分走完整旅程(--help → init → 天真地直接 check → snapshot 首綠 → 常見錯誤),
同場景對照分支 build;另用三個特製頁面(35 層深頁、隨機 id 頁、SVG 頁)做版本對決。

## 版本對決

| 場景 | 0.12.0(使用者今天裝到的) | 準 0.13.0 |
|---|---|---|
| 35 層深頁 snapshot | **exit=2 crash**(擷取成功、落地炸「object cycle」) | ✓ 過,35/35 兩次一致 |
| 隨機 id 頁(玩具) | 被文字錨定救回(3/3)——真實差距見 MDN:48 unmatched → 0 | 3/3,selector 不含隨機 id |
| SVG 頁 | 樹 7 節點(path/g 雜訊入樹;野外 tailwind = 44 unmatched + flaky) | 樹 4 節點(svg 葉子) |
| `--stabilize` | 無此功能 | 連拍偵測不穩定區 + ignore 建議 |
| 有 critical 落差的分數 | 可能顯示 100/100 + GATE FAIL | 封頂 99 |
| 429 / 超深錯誤訊息 | 誤導(查 scope/key、object cycle) | 講人話(Retry-After 換算、DOM 層數) |

結論:0.13 值得儘快發版——深頁 crash 是已發佈版本每個使用者都可能踩的雷。

## 旅程觀察(多數兩版相同)

- **安裝**:`dotnet tool install` 約 5–7 分鐘(self-contained 套件大),一次性成本可接受;
  `parity --version` ✓;裸打 `parity` 印 help ✓;`--help` 長但完整,snapshot 段落
  明寫「No Figma required」✓。
- **首綠時間**:知道要寫 2 行 snapshot config 的人:**snapshot 1.6s + check 1.6s,五秒內綠燈**。
  照 init 指示走的人:被 figmaFileKey/token 擋住,可能直接流失。
- **錯誤訊息抽查**:缺 token(清楚,附 scope 提示)✓;url 指到不存在的檔
  (原生 `net::ERR_FILE_NOT_FOUND`,有完整路徑,可接受);frame 找不到(指名道姓但缺提示,見 D6)。

## 發現

### D1【onboarding 斷層,建議修】init 範本是 Figma-first,snapshot 模式在入口隱形

`parity init` 產出的範本要求 figmaFileKey + FIGMA_TOKEN,完成訊息的四步驟也全是
Figma 路徑——但工具「五秒綠燈」的最快樂勝路徑(snapshot,零 token)在 onboarding
當下完全看不見。沒有 Figma 檔的人(想要重構守門的人、還沒買 Figma 的團隊)是
snapshot 模式的目標客群,卻在第一分鐘就被範本勸退。

修法建議:config 解析本就吃註解(`ReadCommentHandling.Skip`)——範本直接附上
註解掉的 snapshot 替代寫法;init 完成訊息給兩條路(「有 Figma → …」「沒有 Figma →
parity snapshot 三步驟」);或加 `parity init --snapshot`。

### D6【新手陷阱,建議修】init 預設 frame "10:2" × snapshot 模式 = 必撞的錯誤,訊息沒把人接住

走 snapshot 路徑的新手會沿用範本的 `"frame": "10:2"`,錯誤訊息說
「node 10:2 is not present in the design JSON」——指名道姓但沒說**該填什麼**。
補一句「snapshot 基準的 frame id 是 route(例如 "/")」即可把人接住。

  是「圖層名對上 class」——可考慮 tooltip。
