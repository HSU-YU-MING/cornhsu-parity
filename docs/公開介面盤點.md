2. **能實跑的都實跑。** Release 建置後的 `src/Parity.Cli/bin/Release/net10.0/parity.exe`(自報 `parity 0.0.0-dev+2db71e6`):

     `SnapshotDocument`,再對讀端做邊界探測(第 5.3、7.4 節,附錄 B)。

3. **逐檔比對 `git diff v1.1.0..HEAD`**,判斷每項變更動到哪一面(第 10 節)。
4. **semver 判讀依據**:CHANGELOG 1.0.0 節的凍結清單與演進條款五級——
   ① 六面介面破壞 = major;② 量測語意演進 = minor + 「升級必做」;③ 預設值調整 = minor + 顯著標示;
   ④ 行為完全不變的修正 = patch;⑤ minor 若需要重拍基準,工具必須大聲失敗。
   另有兩條附則:action「新增選填 input = minor」;`reason`/`matchedBy` 是開放集合(新增值不算破壞)。
   **本文的延伸解讀**(下文所有「行為會變、卻判 patch」的列都靠它:`failOn` 收緊、容差拒絕負值、
   `--width`/`--height`/`--port` 改報錯、`install-browser` 失敗改回 2、`report`/`push` 拒絕較新的
   `schemaVersion`、npm 啟動腳本的修正、action 改傳 `--out`):**把原本靜默失效、或違反既有文件與 exit code
   契約的行為修回來,判為 patch**。這不是 ④ 的字面意思(④ 只寫「行為完全不變的修正」),而是比照 ⑤
   「大聲失敗」的精神。保守的讀法是這些一律走 minor 並在 CHANGELOG 標示,發佈前由維護者定案。
   **讓 gate 變寬鬆(FAIL 變 PASS)的修正不適用這條延伸解讀**(見 2.5 的 soft 列)。
5. **限制**:本機 `%LOCALAPPDATA%\ms-playwright` 只有 chromium-1228/1234,master 的 Microsoft.Playwright 1.63.0

### 3.2 exit code 契約

用法文字的原句:`Exit codes: 0 = pass; 1 = diffs exceed the gate threshold; 2 = execution error; 3 = match integrity too low (results not trustworthy)`(`Program.cs:722-723`)。

| code | 意義 | 產生處 |
|---|---|---|
| 0 | 通過/指令成功 | 各指令 |
| 1 | `check` 落差超過 gate;`check --baseline` 有新增或惡化;`lint` 有違規 | `Program.cs:133, 185, 211, 381` |
| 2 | 執行錯誤:參數錯、設定錯、檔案找不到、Chromium 未安裝、Figma token 缺、`push` 失敗、`init` 時檔案已存在、`baseline save` 因配對可信度不足拒存 | `Program.cs:39, 46, 582`;`BaselineCommand.cs:41, 84` |
| 3 | 配對可信度不足(0 設計節點、0 配對、低於 `minMatchRate`)。**只有 `check`(含 `--baseline`)會回** | `Program.cs:122, 171` |

契約以外的情況:

- `check --reverse` 永遠回 0(不把關,`Program.cs:99-105`)。
- `install-browser` 透傳 Playwright 的回傳值(`Program.cs:612-614`),失敗時不保證是 2。
- `serve`/`map` 正常結束(Ctrl+C)回 0。
- `baseline save` 遇到配對可信度不足回的是 **2**,不是 3(`BaselineCommand.cs:35-42`)。

#### `check`(`Program.cs:51-257`)
