# 野生實查(路線 B):別人的 Figma 方言 × 官方實作

**日期**:2026-08-11。**動機**:FigmaDesignSource 與 Matcher 此前只吃過作者自己的
Figma 習慣。本輪用兩個公開設計系統的 community 檔(複製進帳號後以
`file_content:read` scope 的 token 讀取),對其官方網站/Storybook 跑 check——
測「別人畫的 Figma」:component/variant 結構、命名習慣、圖層組織。

**素材**:IBM Carbon v11(`qRzJ3fxF1g09NczsrugiXD`)、Ant Design Open Source
(`mXMoU5YGQr0P33RMoc1whS`)。原定第三組 Shopify Polaris 的 community 檔已 404(見 B5)。

## 發現

### B1【正面】FigmaDesignSource 消化野生檔零問題

COMPONENT_SET / COMPONENT / INSTANCE 節點型別、variant 語法命名
(`Type=primary, Shape=standard, …`)、巨型檔案(Carbon 87.2k 使用者的 kit)——
解析全數正常,無 crash、無型別噴錯。自家檔案從沒用過這些結構。

### B2【工作流真相,該寫進文件】變體總表不是可比對的 frame

設計系統 kit 的元件頁是「一張畫滿所有變體的表」,和任何真實頁面在結構上不相交——
實測 1 的 0.2% 配對率不是 bug,是誠實(Matcher 拒絕硬湊)。**路線 B 式的用法要選
「畫一個畫面」的 frame(screen-level),不是「畫所有變體」的 frame(sheet-level)**;
後者配 Storybook 的單一 story(實測 3)才是公平配對。這一段值得進 README 的
「怎麼挑 target.frame」指引。

### B3【可行動,候選規則】通用圖層名的 auto-name 假配對

實測 1 配到的 5 個節點裡,「Content」這個圖層名撞上文件站自己的 `#content` 容器,
產生 width 1969px vs 602px 等 critical 級荒謬落差。**通用名(Content/Header/Title/
Wrapper)在無關頁面上的名稱錨定,是傷害信任的假警報形狀**——對照 XamlContrast
「每條規則來自實查」:候選規則是 auto-name 配對加合理性檢查(例如箱體尺寸數量級
相符才接受,或通用名單字不做 auto-name)。列入 ROADMAP,動工前先蒐集更多樣本。

### B4【方言清單】自家樣本永遠長不出來的結構

空白字串當 frame 名(Ant Design 的三個頂層 frame 名稱是「 」)、分隔線式頁名
(`━ General ━━━`)、variant 語法名、元件內部的 wrapper/Icon/Vector 層。
Matcher 的名稱正規化(`NormalizeName`)對空白名回空字串 → 正確走 no-anchor,
沒有炸;但這些樣態該進測試資料庫。

### B5【生態事實】community 檔會消失

Shopify Polaris 的 community 檔(id 1293611962331823010)已 404。教訓:文件或
設定裡引用 community id 是會腐爛的;真正穩定的是**複製進自己帳號後的 file key**。

### B6【正面,本輪最有價值的訊號】公平配對給出真實的還原度結論

實測 3:Figma kit 裡的按鈕文字節點 ↔ Storybook 渲染的 `<button>`,文字錨定配上,
**字級/字重/行高/字距/顏色全部 0 落差**——IBM 的設計 kit 與程式碼實作是真的一致,
Parity 用數字證實了這件事。這是「工具在野外能給出正確結論」的最強證據:
不一致時誠實列 unmatched(實測 1、2),一致時精確說一致(實測 3)。
