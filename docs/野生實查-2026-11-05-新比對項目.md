# 野生實查 2026-11-05:新比對項目有多吵

對象是這一版新增的 16 個軟落差(文字、順序、對齊、行數、樣式、圖片)。樣本全部是非作者的網站。

## 怎麼量的

每個網站拍一次快照,馬上用同一份快照跑兩次 `check`,視窗 1280×800。第一次 `compare.images: "soft"`,第二次再加 `compare.text: "gate"`。

**頁面沒有改**,所以報出來的都不是真的落差,只有兩種可能:頁面真的在動,或工具有誤報。

本機只有 Chromium 1243,掛成 Playwright 要的 1248 跑的,不是正確版本。

## 讀法

- **行數與文字、邊框、陰影、漸層的樣式,頁面沒變時完全不吵。**
- **有雜訊的 `image`、`opacity`,幾乎都出現在本來就不穩定的頁面。** 台大、Stripe、W3C 的舊硬落差也同時出現,代表頁面兩次載入本來就不一樣(台大有輪播;其他兩站沒有逐一確認原因)。氣象署例外:只有第二次跑多出 5 條 `image`。
- **`image` 是最吵的一項**,而且同一頁兩次跑的條數會變(台大 27 → 0)。預設關閉是對的,不適合改成硬落差。
- **`text` 在快照基準上有 7 條,都在內容會更新的網站**(Stripe 5、BBC 2)。這正是快照預設不比文字的原因。

## 這次抓到並修掉的

- **gov.tw 30 條 `image` 誤報**:圖片在拍快照時本來就沒載入,兩邊畫面一樣,舊寫法只要圖片壞了就報。改成先比畫面。
- **快照大了 34～44%**:大部分節點的值都是預設值。改成只記非預設值,增幅降到 5～18%。
- **Hacker News 沒測到**:它回給機器人的是拒絕頁面(31 個節點),所以第一輪只算 9 個站,這一輪換掉了。

同一批頁面落差 0 條,但這些設計節點只有文字,沒有字體資訊,所以不代表配上之後的屬性比對沒有誤報。

## 真實 Figma(2026-11-06)

用真實的 Figma API 驗欄位解析,再比官方實作。素材是路線 B 複製進帳號的三個公開設計系統 kit,只挑單一元件。

**API 用量**:節點 4 次(每次 7～12 KB)、變體清單 1 次(389 KB)、匯出 frame 1 次,共 6 次,沒有被限流。其他都用快取。

| 元件 | 實作 | 比到的屬性 | 結果 |
|---|---|---|---|
| Carbon 主要按鈕,文字 + 圖示 | Carbon Storybook | 文字節點的字體、`text`、`lineCount`、樣式 | 配上 1/5,0 落差 |
| Carbon 主要按鈕,純圖示 | Carbon Storybook | 邊框、圖片(手動對應) | 圖示 0 落差;padding 4 條,是對應方式造成的 |
| Codex 按鈕 | doc.wikimedia.org | 邊框 1px `#72777D`、底色、圓角(手動對應) | 新屬性 0 落差,和頁面對得上 |
| Ant Design 主要按鈕 | ant.design | 陰影、邊框(手動對應) | 陰影幾何對得上,顏色差異是真的 |

### 真實回應和官方文件一致的

- 預設值會被省略:`opacity`、`primaryAxisAlignItems`、`textCase`、`textDecoration` 都沒有出現。
- `strokes: []` 時 `strokeWeight` 仍然是 1,不能只看粗細。
- `layoutPositioning: "ABSOLUTE"`、`layoutWrap`、`style.textAutoResize` 的位置與值。
- 陰影:`DROP_SHADOW` 的 `offset`、`radius`、`color`。
- 匯出 frame:48×48 的 frame 回來正好是 48×48 的 PNG,裁圖位置正確。

### 這一輪抓到並修掉的

- **透明邊框被報成有邊框**:Carbon 的按鈕是 `border: 1px solid transparent`,設計稿沒有邊框,被報成 0 → 1。
- **跟底色同色的邊框被報成落差**:Ant Design 的設計稿有 1px 邊框,但和底色同色,頁面是透明邊框,兩邊看起來一模一樣,被報成 1 → 0。

兩個都是自己寫的測試頁長不出來的。

### 反向對照:確認比對真的有在比

零落差也可能只是沒比到,所以另外做了三組一定要報的對照,都報了:

| 對照 | 報出來的 |
|---|---|
| Codex 的按鈕對應到沒有邊框的 quiet 按鈕 | `borderWidth` 1 → 0 |
| Ant Design 的按鈕對應到沒有陰影的 text 按鈕 | `shadow` `0px 2px 0px 0px` → none |
| 把匯出的參考圖換成全紅 | `image` 77% different |

### 查到的真實差異

kit 複製進帳號後不會跟著上游改版,所以這些是 kit 過期,不是工具誤報(路線 B 的 B5 看過同一種形狀):Ant Design 的主色 `#1890FF` → `#1677FF`、圓角 2 → 6、陰影色從灰變藍。

### `text` 揭露了假配對

Codex 的 `Text` 圖層靠通用名字配到導覽列,以前只看得到一堆字體落差,現在多一條 `text`:`Button text` → `Toolkit`,一眼看出配錯了。這是路線 B 的 B3,還沒根治,但軟落差 `text` 讓它容易發現。

## 沒量到的

- **設計稿對實作的誤報率**。這幾個都是單一元件,樣本太小,算不出比例。
- **`childOrder`、`mainAxisOffset`、`crossAxisOffset` 完全沒有真實資料**:單一按鈕裡沒有兩個以上固定尺寸的子元件。要有「畫一個畫面」的設計稿對它的實作才比得到。
- **Figma 的非預設值**:漸層(含方向)、斜體、底線、大小寫、每邊不同的邊框粗細,這批元件裡沒有。
- 手動對應與合成外框造成的 `offsetX`、`offsetY`、`padding` 落差不算工具誤報,也沒有算進上面的結果。

要決定哪些屬性改成硬落差,還缺畫面層級的設計稿。
